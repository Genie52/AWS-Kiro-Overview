01 · How it codes

Vibe coding & spec-driven development

Two ways to build with the same agent: talk it through, or plan it first.
01 / 07

Vibe coding is a conversation: describe what you want, Kiro reads your project, makes the change, and you iterate. Spec-driven development adds a plan first: Kiro turns an idea into requirements, a design and a task list that you review before any code is written.

Vibe chat

Ask or instruct in plain language. Kiro tells questions from requests. Add context with #codebase, #file, #git diff, #terminal or #mcp.

Specs

Three files per feature: requirements.md (user stories, acceptance criteria), design.md (architecture, diagrams) and tasks.md (trackable steps). Bug fixes use bugfix.md.

Steering

Markdown files in .kiro/steering/ teach Kiro your stack and conventions once. Load them always, by file pattern, on demand or automatically. AGENTS.md works too.

Hooks & sub-agents

Hooks run a command or prompt on events such as a file save or tool call, for example lint on save. Sub-agents take focused work in their own context, in parallel.

Try saying

“Create a React component for a user profile page.” (vibe)
“New spec: add password reset to our login flow.” (spec)

02 · Where work happens

Team & comms tools

Kiro works with the systems your team already uses, through the Model Context Protocol (MCP).
02 / 07

MCP is an open protocol that lets Kiro call tools on external servers. Connect a server for your tracker, code host or chat tool, and Kiro can read an issue, comment on it, open a pull request or draft a reply from the same conversation.

MCP servers

Add local or remote servers in .kiro/settings/mcp.json, or install with one click from the Kiro MCP directory. Kiro asks you to confirm before it changes your config.

Repos & trackers

The curated directory includes GitHub, GitLab and Atlassian (Jira, Confluence). The GitHub server covers repos, branches, issues and pull requests.

Powers

Bundles of MCP tools plus know-how that load only when the task needs them, so context stays small. Examples: Datadog, Figma, Postman, Stripe.

Pull-request loop

On Kiro Web the agent opens PRs and answers review comments. /kiro all or /kiro fix says which to address. It never merges for you.

Try saying

“Find open bugs labeled login and summarize them by severity.”
“Create an issue in my repository about the login bug.”

03 · Grounded in your data

Data & knowledge

Answers built from your real schemas, documents and docs, not guesses.
03 / 07

Kiro already reads your code. MCP servers let it also look at databases, data lakes and knowledge bases, so the SQL, pipelines and answers it writes match the tables and documents that actually exist.

Databases & warehouses

AWS Labs MCP servers for DynamoDB, Aurora PostgreSQL and Redshift. The Kiro directory adds Snowflake, Databricks and MongoDB.

Data lakes

The S3 Tables server works with Apache Iceberg tables stored in Amazon S3, so Kiro can see table layouts before it writes a query or job.

Knowledge bases

Search Amazon Bedrock Knowledge Bases, vector stores such as Pinecone, graph data in Neo4j, and AWS documentation itself.

Project knowledge

Steering files can link live files, for example #[[file:api/openapi.yaml]], so your API spec or data dictionary stays in context.

Try saying

“Look at the orders table and write a query for last week's revenue by region.”
“Search our knowledge base for the refund policy and update the FAQ page.”

04 · Ships infrastructure

Infrastructure as code, any cloud

Kiro writes the templates; MCP tools check them before you deploy.
04 / 07

Kiro writes AWS CDK, CloudFormation and Terraform like any other code. Add the AWS IaC MCP server and it can also validate templates, check them against security rules, and explain why a deployment failed.

Write

CDK in TypeScript, Python, Java, C# or Go. CloudFormation in YAML or JSON. Terraform for AWS and other clouds.

Validate

Runs cfn-lint on a template and returns each error with a suggested fix and its line number.

Comply

Runs cfn-guard security and compliance rules on the template before anything is deployed, with remediation guidance.

Troubleshoot

Point it at a failed stack: it matches more than 30 known failure patterns and links the related CloudTrail events.

Try saying

“Write a CDK stack for a versioned, KMS-encrypted S3 bucket, then check it for compliance.”
“Troubleshoot my CloudFormation stack named my-app-stack in us-east-1.”

05 · Choice of brain

Frontier and open-weight models

Pick a model per task, or let Auto pick for you.
05 / 07

Kiro offers models from Anthropic, OpenAI and open-weight providers. Auto sends each task to a suitable model and is the cost baseline (1.0x). Every other model uses more or fewer credits than Auto for the same task.

Auto

The recommended starting point for most work. It balances quality and credit cost task by task, so you don't have to choose.

Frontier

Claude Opus 5.5 and Sonnet 5.5, and GPT-5.6 in three tiers: Sol, Terra and Luna. All have a 1M-token context window.

Open-weight

MiniMax M2.5, GLM-5, Qwen3 Coder Next, DeepSeek 3.2 and Kimi K3. Most cost a fraction of Auto.

Effort & fallback

Raise reasoning effort for hard problems or lower it for speed. A fallback model can answer when your chosen model is unavailable.

Try saying

Pick Opus 5.5: “Refactor the payments service to the new auth middleware.”
Pick Haiku 5.5: “Write docstrings for every function in utils/.”

06 · Runs where you work

IDE · CLI · Web · Mobile

Four ways to talk to one agent; your configuration follows you.
06 / 07

Every surface is a front end to the same agent harness. A steering file, custom agent, permission rule or MCP server you set up once behaves the same in the editor, the terminal, the browser and on your phone. Commit .kiro/ and the whole team gets it.

IDE

Desktop editor with inline diffs, checkpoints, spec panes and editor problems shared with the agent. Agent Focus Mode manages cloud sessions.

CLI

kiro-cli in your terminal. Headless mode runs prompts in CI/CD with API keys. ACP brings the agent into other editors.

Web

app.kiro.dev with no setup. Works in a cloud sandbox and delivers pull requests. Default, Spec and Autonomous modes.

Mobile

iOS app in early access through TestFlight. Start and steer cloud sessions from your phone.

Try saying

On Web, Autonomous: “Upgrade this repo to Node 22, fix the tests and open a PR.”
Close the laptop, then check progress and approve from your phone.

07 · Governed by your enterprise

Enterprise controls

Admins set identity, model, tool and data policies centrally in the Kiro console.
07 / 07

Kiro Enterprise is managed from the Kiro console in AWS. Admins decide who can sign in, which models and MCP servers people may use, how data is encrypted and logged, and how network traffic reaches Kiro. Policies can be set per organization or per account.

Identity

Sign-in through IAM Identity Center, Okta or Microsoft Entra ID. AWS GovCloud (US) also supports a custom OIDC provider.

Governance

Approved model list and default model. MCP on, off or limited to a registry. API keys, web tools and Cloud Sessions each switch on or off.

Data protection

Enterprise content is not used for service improvement. TLS 1.2+ in transit. AWS-owned KMS keys by default, or your own customer-managed key.

Audit & network

Prompt logging from IDE and CLI to an S3 bucket in your account. PrivateLink endpoints keep traffic on the AWS network.

Admin first steps

Connect your identity provider, then subscribe users or groups.
Under Settings → Shared settings, set approved models and the MCP registry URL.
